## High-level data outputs

Primary output roots:

- `data/tie_points_shards/`
  - tie-point + pair + slope metadata shards
  - manifest: `0000_manifest.pkl`
- `data/graph_data_shards/`
  - per-`n` graph data shards
  - manifest: `0000_manifest_p<steps>.pkl`
- `data/tieCuspSlopes.pkl`
  - cusp-only sidecar derived from the tie shards
  - generated by `OBDsaveSourceData.py --save-cusp-data`
- `log/`
  - timestamped CSV run logs for tie pathway

## Pathway 1: tie points + slope metadata

Code path: `save_tie_points(...)` → `_compute_tie_shard(...)` → `_tie_records_for_n(...)`, and loaders around `load_tie_points_from_shards(...)`.

### Tie manifest format

Manifest file: usually `data/tie_points_shards/0000_manifest.pkl`

Top-level manifest schema:

- `format`: `"obd.tie_points_slope.shards.v2"`
- `created_at`: timestamp string
- `shards_dir`: absolute path
- `obd_core_version`: version of [OBD-core](https://github.com/dperlman/OBD-core) that computed the shards
- `n_entries`: dict keyed by stringified `n`

Each `n_entries[str(n)]` has:

- `n`: `int`
- `shard_path`: relative shard path string
- `tie_points`: `int`
- `local_min`: `int` — the number of cusps (certified local minima of E)
- `max_local_min_p`: `float | None` — p of the last cusp
- `n_checked`: `int` — tie points whose verdict needed interval or exact arithmetic
- `n_unresolved`: `int` — tie points that 200-digit interval arithmetic could not settle (0 so far)
- `updated_at`: timestamp string

**v1 is refused.** The v1 format (before 2026-10-05) stored one-sided slopes estimated by finite differences of E. On each concave piece between tie points every secant is biased inward by about |E''|·eps/2, so v1's `slope_right - slope_left` was negative at 31% of tie points at n = 50 and 80% at n = 1000, it missed real cusps whose left slope is just below 0, and it labelled some tie points "maximum", which is impossible. The loaders raise on a v1 manifest, and `save_tie_points` rebuilds every n when it finds one.

### Shard payload format

Each tie shard payload (`tie_points_nXXXX.pkl`) is a dict:

- `format`: `"obd.tie_points_slope.n_shard.v2"`
- `n`: `int`
- `obd_core_version`: `str`
- `float_by_n`: `np.ndarray` of tie `p` values (`dtype=float64`), sorted
- `float_with_pairs_by_n`: `list[tuple[float, list[tuple[int, int]]]]` — one pair per tie point; the center tie `p = 1/2` carries the canonical pair `((n-1)//2, n-(n-1)//2)` and stands for all mirror pairs `i + j = n`
- `tie_slope_by_n`: `list[dict]`, aligned with the two lists above

### tie_slope_by_n per-point record

- `p`: `float` — the tie point
- `expected_sorted`: `float` — E(n, p) at the tie point
- `slope_left`: `float` — E'_-, the exact left slope
- `slope_right`: `float` — E'_+, the exact right slope
- `log10_D`: `float` — log10 of the slope jump D = E'_+ − E'_- = (j−i)·f(i)/(p q) > 0, the size of the kink
- `is_cusp`: `bool` — certified local minimum of E at this tie point
- `decided_by`: `str` — `"double"`, `"iv50"` / `"iv100"` / `"iv200"` (interval arithmetic at that many digits), `"exact"` (integer arithmetic, for adjacent pairs whose p* is rational; needed at n = 2, where S_- is exactly 0), `"symmetry"` (the center tie) or `"UNRESOLVED"`

**Use `log10_D` for the slope jump, never `slope_right - slope_left`.** D spans hundreds of orders of magnitude (the median at n = 1000 is below double range) while the slopes are O(1)–O(n), so the difference of the two slopes is 0 or rounding noise for most tie points. `log10_D` comes from the pair mass and is exact.

There is no "maximum" type: a tie point is never a local maximum of E (the kink is always convex, D > 0), so every tie point is either a cusp or neither.

### How the tie values are computed

All of it comes from `obd_core.tie_table(n, both_halves=True)` ([OBD-core](https://github.com/dperlman/OBD-core), the same code as [ordered-binomial-cusps](https://github.com/dperlman/ordered-binomial-cusps)):

1. Every pair `0 <= i < j <= n` with `i + j > n` (so p* > 1/2) is screened by a numba kernel: masses by recurrence, normalised by their own sum, ranks by a two-pointer merge with the ranking just left of p*.
2. The left slope is S_-/(p q) with S_- = Σ w_k f(k)(k − n p); the right slope adds the kink (j−i)·f(i)/(p q). No finite differences.
3. A tie point is a cusp iff S_- < 0 < S_+. That is decided in double precision with a margin, and anything near the margin, or with masses whose order double precision cannot resolve, goes to mpmath interval arithmetic at 50, 100 and then 200 digits.
4. p = 1/2 is added as the axis row; the p* < 1/2 half is the mirror image under E(p) = E(1 − p): (i, j) at p* becomes (n−j, n−i) at 1 − p*, with the same E, D and verdict, and the slopes swapped and negated.

### Tie CSV log columns

`save_tie_points` writes `log/tie_points_verbose_<timestamp>.csv`:

- run id: `run_started_at`, `n`
- timing: `compute_sec`, `write_sec`, `iter_total_sec`
- counts: `tie_points`, `local_min` (cusps), `max_local_min_p`, `n_checked`, `n_unresolved`

## Pathway 2: graph data shards

Code path: `save_graph_data(...)` and `load_graph_data_from_shards(...)`.

### Graph manifest format

Manifest filename embeds p-grid density:

- `0000_manifest_p<steps>.pkl`

Top-level keys:

- `format`: `"obd.graph_data.shards.v2"`
- `created_at`, `updated_at`
- `p_steps`: `int`
- `p_values`: `np.ndarray` (`float32`)
- `n_min`, `n_max`
- `shards_dir`
- `n_entries`

Each `n_entries[str(n)]`:

- `n`
- `shard_path`
- `rows` (= `p_steps`)
- `p_steps`
- `k_count` (= `n+1`)
- dtype descriptors:
  - `dtype_y`: `"float32"`
  - `dtype_perm`: `"uint16"`
  - `dtype_expected_sorted`: `"float32"`
  - `dtype_expected_sorted_slope`: `"float32"`
- `updated_at`

### Graph shard payload format

Each graph shard dict:

- `format`: `"obd.graph_data.n_shard.v2"`
- `n`: `int`
- `p_steps`: `int`
- `y`: `np.ndarray`, shape `(p_steps, n+1)`, `float32`
- `perm`: `np.ndarray`, shape `(p_steps, n+1)`, `uint16`
- `expected_sorted_by_p`: `np.ndarray`, shape `(p_steps,)`, `float32`
- `expected_sorted_slope_by_p`: `np.ndarray`, shape `(p_steps,)`, `float32`

### Graph calculation notes

- PMF is built in float64 using log-domain binomial math (`gammaln`, `log`, `exp`) for stability.
- Stored arrays are cast to compact dtypes (`float32` / `uint16`).
- `expected_sorted_slope_by_p` uses `np.gradient` over the `p_values` grid.

## Pathway 3: cusp sidecar

Code path: `save_cusp_data_from_tie_shards(...)` (`--save-cusp-data`); load with `load_cusp_data(...)`.

Purpose: the certified cusps alone, in one compact file, so cusp plots and analysis do not need to load every tie point. The values are copied from the tie shards; nothing is recomputed.

### File schema: tieCuspSlopes.pkl

Top-level dict keys:

- `format`: `"obd.tie_cusp_slopes.v4"`
- `created_at`, `updated_at`
- `source_tie_manifest`: absolute source tie manifest path
- `n_entries`: dict keyed by `str(n)`

Each `n_entries[str(n)]`:

- `n`: `int`
- `center_index`: `int` (index in the tie array of `p = 0.5`)
- `center_p_float`: `float`
- `count_cusps`: `int`
- `updated_at`: timestamp string
- `records`: `list[dict]`, one per cusp:
  - `n: int`, `p_float: float`
  - `tie_index: int` — signed, relative to the center tie (`0` = `p = 1/2`, which is always a cusp)
  - `is_center_tie: bool`
  - `pairs: list[tuple[int, int]]`
  - `expected_sorted`, `slope_left`, `slope_right`, `log10_D`: `float`, as in the tie record
  - `decided_by: str`

## Loader return structures (summary)

### `load_tie_points_from_shards(...)`

Returns:

- `float_by_n: dict[int, np.ndarray]`
- `float_with_pairs_by_n: dict[int, list[tuple[float, list[tuple[int, int]]]]]`
- `tie_slope_by_n: dict[int, list[dict]]`

### `load_graph_data_from_shards(...)`

Returns:

- `format`, `n_min`, `n_max`, `p_steps`, `p_half_start`
- `p_values: np.ndarray(float32)`
- `rows_by_n: dict[int, dict[str, np.ndarray]]` with keys:
  - `y`, `perm`, `expected_sorted_by_p`, `expected_sorted_slope_by_p`
- `manifest_path`

### `load_cusp_data(...)`

Loads `data/tieCuspSlopes.pkl` (or another path). Validates `format == "obd.tie_cusp_slopes.v4"`. Optional `n_list` restricts which `n` blocks are loaded; `require_all` mirrors the tie/graph loaders (missing requested `n` raises).

Returns:

- `format`, `created_at`, `updated_at`, `source_tie_manifest`
- `n_entries: dict[int, dict]` — string keys in the file are normalized to `int` keys. Each inner dict is the per-`n` block above: `n`, `center_index`, `center_p_float`, `count_cusps`, `updated_at`, `records`.

## Practical interpretation notes

- Every tie point is either a cusp (`is_cusp`) or nothing; there are no maxima at tie points.
- For the kink size use `log10_D`; explorers and heatmaps show it as the `d` field.
- `expected_sorted_slope_by_p` in the graph shards is `np.gradient` of E over the p grid: a secant slope across all the kinks inside each grid step, not E'(p) and not related to D.
